# 自製導航地圖（Homemade Navigation Map）

> 資料結構課程專題｜以 Python 實作的智慧交通路徑規劃模擬系統。隨機生成有向道路網，依車種限制與使用者條件搜尋所有可行路徑，以 Heap 排序後輸出，並在使用者選定路徑後更新路段車流量。

---

## 摘要（Abstract）

導航系統的核心是「在圖上找路」。真實世界的問題比最短路徑複雜：不同車輛能走的路不同，收費不同，道路壅塞程度也會隨車流改變。

本專題以資料結構為主軸，模擬一個小型城市交通網。系統隨機產生 3 至 7 個路口與有向道路，每條道路帶有長度、寬度、類別、車流量與速率係數。使用者選擇車種、起點、終點，並可指定必經與避開的地點。系統以深度優先搜尋列出所有符合條件的路徑，計算每條路徑的距離、時間與收費，再以 9 種方式排序。使用者選定路徑後，該路徑的車流量加 1，並重新計算速率，地圖同步更新。

## 研究動機（Motivation）

資料結構課程涵蓋圖、堆積、堆疊、遞迴、排序與搜尋。這些概念單獨練習時，容易停在「會寫」的層次。

導航系統剛好能把它們串在一起：路網是圖，找路是搜尋，排序是 Heap，輸出是堆疊。加上車種繼承與錯誤處理，一個題目涵蓋課程大部分內容。

## 資料結構與技術對照（Data Structures Used）

| 概念 | 應用位置 | 說明 |
| --- | --- | --- |
| 圖（Graph） | `Map.py` | 節點以字典保存，每個節點記錄鄰居；邊另以串列保存，包含完整屬性。有向圖 |
| 遞迴與深度優先搜尋 | `main.py`、`Output_route.py` | `hasRoute` 判斷起終點是否連通；`Output_Route.dfs` 列舉所有不重複經過節點的路徑，並用回溯還原狀態 |
| 堆積（Heap） | `Sequence.py` | 以 `heapq.nsmallest` 依距離、時間、收費排序 |
| 堆疊（Stack） | `Sequence.py` | 排序結果由串列尾端依序 `pop` 輸出 |
| 類別與繼承 | `Vehicle.py` | 父類別 `Vehicle`，子類別 `Motor`、`Car`、`Truck`、`Emergency`，各自覆寫 `eligibility()` |
| 多型 | `main.py` | 以車種物件決定可選的排序選項與通行資格 |
| 例外處理 | `main.py`、`Update.py`、`Vehicle.py` | 以 `try / except ValueError` 處理選單輸入；父類別以 `NotImplementedError` 強制子類別實作 |
| 串列與字典 | 全部 | 保存路徑、節點、鄰居與車牌 |

## 系統設計（System Design）

### 模擬地圖的生成

地圖每次執行時隨機生成。

| 項目 | 規則 |
| --- | --- |
| 節點 | 3 至 7 個，依序命名為 A、B、C… |
| 邊 | 有向；每個節點各有相同數量的出邊 |
| 收費站 | 隨機挑選節點，以淺藍色標示 |
| 道路寬度（weight） | 1 至 5 的整數 |
| 道路長度（length） | 1 至 20 的整數，單位為公里 |
| 道路類別（category） | `normal`（一般）、`highway`（高速公路）、`residential`（住宅區） |
| 車流量（traffic） | 1 至「寬度 × 40」的整數 |

**速率係數（rate）** 依車流量與寬度的比值決定：

| 車流量 | 速率係數 | 意義 |
| --- | --- | --- |
| < 寬度 × 10 | 1 | 順暢 |
| 寬度 × 10 至 × 20 | 0.8 | 略為壅塞 |
| 寬度 × 20 至 × 30 | 0.6 | 壅塞 |
| 其餘 | 0.4 | 嚴重壅塞 |

### 車種

| 車種 | 速度（公里／小時） | 收費（元／收費站） | 通行限制 |
| --- | --- | --- | --- |
| 機車 `Motor` | 60 | 10 | 不可行駛高速公路 |
| 汽車 `Car` | 80 | 30 | 無 |
| 貨車 `Truck` | 70 | 50 | 不可行駛住宅區道路 |
| 緊急用車 `Emergency` | 100 | 0 | 無 |

### 路徑計算

- **距離：** 路徑上每條邊的長度加總。
- **時間：** 每條邊的長度乘上速率係數，再除以車速，加總。
- **收費：** 路徑中每經過一個收費站節點（由該節點出發時），加收該車種的費用。

### 排序方式

排序選單依車種調整。緊急用車不顯示收費相關選項，機車不顯示「避開高速公路」。

| 類型 | 選項 |
| --- | --- |
| 依距離 | 由近到遠、由遠到近 |
| 依時間 | 由快到慢、由慢到快 |
| 依收費 | 由低到高、由高到低 |
| 過濾後依距離排序 | 避開收費站、避開高速公路、避開交通壅塞（速率係數為 0.4 的路段視為壅塞） |

### 主流程

```
建立地圖並輸出圖片
      │
      ▼
選擇車種 → 輸入車牌 → 輸入起點、終點（DFS 檢查是否連通）
      │
      ▼
指定必經地點與避開地點（可略過）
      │
      ▼
DFS 列出所有符合條件的路徑（無路徑時重新指定）
      │
      ▼
選擇排序方式 → Heap 排序
      │
      ▼
列出前 10 條路徑，使用者選擇其一
      │
      ▼
路徑上各邊車流量加 1，重算速率，重新輸出地圖
      │
      ▼
回到「選擇車種」，可連續模擬多輛車
```

### 輸入驗證

| 項目 | 規則 |
| --- | --- |
| 車種 | 只接受 1 至 5；輸入 5 離開系統 |
| 車牌 | 共 8 碼，格式為「三碼大寫英文－四碼數字」，例如 `ABC-1234`；同一次執行中不可重複 |
| 起點與終點 | 必須存在於地圖；終點不可等於起點；兩者之間必須連通 |
| 必經地點 | 必須存在；不可為起點或終點 |
| 避開地點 | 必須存在；不可為起點、終點，或已列為必經 |
| 排序方式 | 必須在當前選單範圍內 |

## 安裝與執行（Installation）

**環境需求：**

- Python 3.11（儲存庫內的快取檔為此版本）
- Python 套件 `graphviz`
- Graphviz 軟體本體（需要 `dot` 指令）

```bash
git clone https://github.com/Fu-Pei-Yin/homemade_navigation_map.git
cd homemade_navigation_map

pip install graphviz
# 另需安裝 Graphviz 軟體：
#   Windows：https://graphviz.org/download/ ，安裝時勾選加入 PATH
#   macOS：  brew install graphviz
#   Ubuntu： sudo apt install graphviz

python main.py
```

程式啟動後會產生地圖並自動開啟圖片，接著在終端機依提示操作。

## 限制與未來工作（Limitations and Future Work）

前四項已實際執行程式碼重現確認，其餘為讀程式碼得出的結果。

**限制**

- **地圖生成可能卡住。** 每個節點的出邊數，最多可等於節點總數，但每個節點最多只能連向其他節點。出邊數等於節點數時，迴圈永遠湊不齊，程式停住。節點數為 n 時，機率約為 1／n。
- **通行限制沒有生效。** `main.py` 的 `sorted_route` 有檢查車種能否通行，但檢查結果沒有影響輸出。機車仍可能拿到含高速公路的路徑，貨車仍可能拿到含住宅區道路的路徑。
- **緊急用車的排序選單第 6 項對應錯誤。** 選單顯示「避開交通壅塞」，實際執行的是「收費由高到低」。
- **壅塞路段的時間反而算得比較短。** 時間公式為長度 × 速率係數 ÷ 車速。速率係數越小代表越壅塞，乘在分子會讓時間變短。合理的寫法是長度 ÷（車速 × 速率係數）。
- **路徑數量隨節點數快速成長。** DFS 列舉所有不重複路徑，節點少時沒有問題，節點數增加後路徑數會爆炸。
- **只有文字介面。** 使用者需要看著地圖圖片，再在終端機輸入節點名稱。
- **規劃文件與實作有落差。** 展示流程文件規劃 3 至 20 個節點、雙向道與單向道並存、車道數 1 至 4；實作為 3 至 7 個節點、全為單向邊、以寬度取代車道數。

**未來工作**

- 修正地圖生成的出邊數上限，並保證圖形連通。
- 讓 `sorted_route` 真正排除不可通行的路徑。
- 修正緊急用車的選單對應，並改用字典把選項名稱對到函式，避免用編號硬寫判斷。
- 修正時間公式，使壅塞路段時間變長。
- 加入 Dijkstra 或 A* 演算法，以最短路徑取代全部列舉，並與現行 DFS 比較效能。
- 加入雙向道路與多車道設定，貼近企劃書原意。
- 以圖形介面（例如 Tkinter）讓使用者直接點選地圖上的節點。
- 補上 `.gitignore`，排除 `__pycache__`。
